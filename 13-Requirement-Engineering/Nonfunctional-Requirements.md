# Nonfunctional Requirements

Functional requirements describe what the system does; NFRs describe qualities/constraints under which it must operate.

Categories: performance, availability, reliability, security/privacy, accessibility, scalability, compatibility, observability, maintainability, recovery and compliance.

## Make measurable where meaningful
“Fast” is weak. Prefer a defined user journey/percentile/target based on actual product need.

## Mobile examples
Supported OS versions, offline behavior, crash-free target, accessibility, API compatibility and launch/performance expectations.

## Cloud examples
Availability objective, RTO/RPO, throughput assumptions, data residency and monitoring requirements.

Do not invent numeric targets; derive/approve them with stakeholders.
