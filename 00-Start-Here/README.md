# Start Here

This playbook is designed for **learning, practical execution and interviews**.

## How to use it
### I need to learn a topic
Read the canonical topic README → examples → scenarios → troubleshooting → Q&A.

### I need to execute/review work
Use the relevant **checklist** or **playbook**, then follow links to deeper material.

### I have an interview soon
Use Cheat Sheets + Interview Master. For a multi-day window, add scenarios and system-design practice.

### I need to make a technical decision
Find the canonical architecture/topic page and focus on **constraints, alternatives, trade-offs, failure modes and validation**.

## Depth legend
- **DEEP:** able to explain internals, trade-offs, debug scenarios and lead technical discussion.
- **STRONG:** able to design/review solutions and challenge assumptions with solid working knowledge.
- **WORKING:** able to collaborate effectively, understand architecture and ask the right questions.
- **AWARENESS:** know what it is, why it matters and when specialist input is needed.

Depth is a learning target, never a fabricated experience claim.

## Content markers
Use these labels when useful:
- **Fact** — established technical behavior.
- **Assumption** — defined for an example/design exercise.
- **Recommendation** — context-dependent guidance.
- **Illustrative example** — educational, not a claim about past work.
- **Version-sensitive** — verify against current official documentation.
