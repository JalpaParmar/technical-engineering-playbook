# HTTP & REST

Understand methods, status codes, headers, caching and transport semantics. GET should be safe/read-oriented. PUT is conventionally idempotent replacement/upsert of a known resource; PATCH is partial change; POST is not inherently idempotent.

Use machine-readable errors for validation, authentication, authorization, conflict, rate limiting and server failures. Mobile clients live across backend releases, so backward compatibility is a core API concern.
