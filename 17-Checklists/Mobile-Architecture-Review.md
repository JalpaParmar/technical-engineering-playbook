# Mobile Architecture Review — Lead/TPM Checklist

## Before review
- [ ] business-critical flows known
- [ ] nonfunctional requirements explicit
- [ ] diagrams reflect current proposal
- [ ] key assumptions written

## Review
- [ ] state/data ownership clear
- [ ] API compatibility addressed
- [ ] offline/failure behavior defined
- [ ] auth/security boundaries sound
- [ ] concurrency risks considered
- [ ] persistence/migrations addressed
- [ ] observability included
- [ ] test strategy credible
- [ ] release/feature-flag strategy defined
- [ ] complexity justified by requirements

## Decision
- [ ] alternatives/trade-offs documented
- [ ] unresolved risks have owners
- [ ] ADR needed for major decision
- [ ] follow-up date/validation identified
