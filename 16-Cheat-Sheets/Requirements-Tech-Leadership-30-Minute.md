# Requirements + Technical Leadership — 30-Minute Revision

**0–5:** problem/outcome, ambiguity/open questions.  
**5–10:** stories/acceptance/NFRs.  
**10–15:** dependencies, estimation, scope/change.  
**15–20:** architecture/code review and decisions.  
**20–25:** debt, mentoring, cross-team conflict.  
**25–30:** release/incident leadership.

Speak aloud: API late? scope creep? engineer disagreement? deadline risk? ambiguous requirement? executive asks for root cause before evidence?
