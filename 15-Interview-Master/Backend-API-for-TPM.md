# Backend/API for TPM — Interview Pack

A TPM should be able to challenge API readiness without pretending to implement every backend component.

Ask about contract, auth, errors, compatibility, idempotency, pagination, performance, security, test environment and observability.

## Scenario
Backend API is late: freeze contract/examples, identify blocking endpoints, use mocks where safe, parallelize clients, track integration risk, and validate against the real API before calling the feature complete.

## Scenario
API changed after mobile release: restore compatible backend behavior where safe, assess installed client versions, mitigate feature exposure, and establish version/deprecation governance.
